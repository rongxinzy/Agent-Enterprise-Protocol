# Security Policy

Security reports must not include production credentials, customer data,
License private keys, signing seeds, or unredacted logs.

Report a vulnerability through this repository's private GitHub vulnerability
reporting channel. Do not open a public issue for an unpatched vulnerability.
Include the affected commit or release, impact, prerequisites, reproduction
steps, and a minimal non-sensitive proof of concept. If private reporting is
not available, contact the repository owners through an established private
organizational channel before sharing technical details.

The latest release candidate and current `main` branch receive security fixes.
Older development snapshots are not supported. A disclosure date is agreed
after triage and remediation; do not publish details before that date.
