# Data Plane Contract

The M3 data-plane contract separates the control plane's tenant-scoped desired state from the gateway reconciler's observed state.

`POST /aep/v1/admin/data-plane/publish` is the recommended publication path and makes the model catalog the single source of truth for gateway routes. The server derives a route from every catalog model with `sourceType: gateway`, `protocol` of `openai-compatible` or `anthropic`, and a complete endpoint and upstream model, then atomically replaces the desired state. OpenAI-compatible models derive the ai-proxy `openai` provider route. Anthropic models render as a self-contained EnvoyFilter passthrough under a per-model path prefix — clients use the gateway base URL plus the sanitized model ID as the path prefix (for example `http://<gateway>/bench-anthropic`, with the anthropic SDK appending `/v1/messages`) — and must carry an absolute http(s) endpoint; they never set a `providerType`. Disabled models ride along as `enabled: false` routes so the reconciler deletes resources a route previously owned; they render nothing. A model bound to a Credential maps to the conventional Secret `aep-credential-<credentialId>` key `api-key` in `higress-system`; the Secret value is provisioned by the deployment Secret system and never crosses the API. When the derived state equals the stored state, publishing is an idempotent no-op; otherwise the server assigns a content-addressed `catalog-` revision unless the caller provides an explicit `revision`.

`PUT /aep/v1/admin/data-plane/desired-state` is the deprecated manual escape hatch for operator-authored states (for example, routes that need Higress' native `deepseek` provider type). It accepts a deterministic `revision` and model routes. A route may refer to a Kubernetes Secret or external Secret by `name`, `namespace`, and `key`; the API never accepts or returns provider Secret values. Anthropic routes take precedence in validation: their `providerType` must be omitted and their endpoint must be an absolute http(s) URL. Repeating the same revision is idempotent. Both entry points write the same desired state with unchanged content-hash semantics.

`GET /aep/v1/admin/data-plane/status` reports `pending`, `applying`, `ready`, `degraded`, or `error`, plus the observed revision, content hash, resource count, and a bounded failure message. Its `catalogComparison` field lists catalog-publishable models missing from the desired routes, desired routes the catalog would not publish, and per-field route mismatches, so consoles can show unpublished or drifted models. A mismatch describes what a catalog publish would change; it is not necessarily an error. The status is informational and does not grant access to Secret material.

PR #17 implements the reconciler that consumes this contract. It must apply only the desired revision, calculate a canonical SHA-256 content hash, use fail-closed credentials, and write status transitions without logging route secrets.
