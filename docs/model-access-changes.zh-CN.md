# 模型授权事务变更信号

这是[有效授权发布 #338](https://github.com/rongxinzy/Agent-Enterprise-Protocol/issues/338)
的数据库输入阶段。迁移 `052_model_access_changes.sql` 为**现有 publication relay**
增加持久、可合并的 outbox 输入；尚未启用消费者、Kubernetes writer 或新鉴权链路。
独立的授权 CR 契约见 [#344](https://github.com/rongxinzy/Agent-Enterprise-Protocol/pull/344)。
本阶段不代表 DB→CR→数据面的业务链路已完成。

## 存储与影响范围

`model_access_changes` 每个 `(deployment_id,user_id)` 一行，数字员工使用自己的
`users.id`，不用所有者身份。只记录递增信号版本、已确认版本和时间，不复制凭据、
令牌、策略载荷或身份详情。迁移时为已有用户生成一次初始信号；多个变更可合并。
该版本是待处理工作的护栏，既不是事件次数，也不是 CR 发布序号。

数据库触发器让业务写入与信号**在同一事务内提交或回滚**，覆盖 GORM、pgx 等写入。
依赖展开覆盖直接角色、团队成员与默认角色，并保守保留停用关系的成员，以免漏掉
原来有效的权限；实际有效角色仍以 `user_effective_roles` 为准。

| 业务变更 | 产生信号的主体 |
| --- | --- |
| 账号创建、删除、状态/类型、密码及安全状态变化 | 当前用户 |
| 直接角色或团队成员变化 | 变更前后的用户 |
| 角色启停、删除、权限绑定变化 | 直接或经团队继承该角色的用户 |
| 团队启停、删除、默认角色变化 | 该团队成员 |
| 模型授权新增、删除、主体迁移、到期时间编辑 | 新旧授权涉及的主体 |
| 模型启停或删除 | 对该模型有授权依赖的主体 |
| 会话创建、撤销或删除 | 该会话所属用户 |
| 员工 profile 创建、删除、到期配置变化 | 员工自身 |
| 许可证或激活创建、删除、撤销、有效签名状态变化 | 该部署用户，不影响其他部署 |

删除父资源前先捕获影响范围，避免级联删除让成员和授权依赖消失。删除用户保留其
信号，以供后续发布拒绝墓碑；ID 重用也不会重置版本。部署级联不创建孤立信号，
现有业务外键限制保持生效。

依赖展开与成员/授权写入复用现有部署级网关配置事务锁
`hashtextextended(deployment_id,101)`，拿锁后使用新快照读取影响范围。否则新增成员
可能先按旧策略完成发布，而并发策略变更又漏掉其尚未提交的成员关系。真实数据库
测试覆盖两个提交顺序。该锁只串行化同部署配置变更，不进入模型请求；PostgreSQL
死锁/序列化错误仍需调用方重试，不会提交一半的业务数据或信号。

显示名称、描述、邮箱、主角色/主团队标记、会话/激活心跳、refresh token 轮换以及
相同值 UPDATE 不触发策略信号。仓库对相同绑定进行删除再插入仍可能产生信号，后续
消费者必须比较最终有效结果的规范化内容，再决定是否发布；收到信号本身不能清除
有效热缓存，更不能清除无关主体的缓存。

历史 user/team 授权依赖只用于安全迁移和撤销，不代表引入直接资源授权。目标设计
继续遵守“资源仅赋予角色”。本迁移不修改现有授权 API 或 entitlement 计算。

## 发布边界与待完成事项

`version > acknowledged_version` 表示待处理。后续消费者必须在一个事务内捕获有效
快照、生成持久发布/outbox 并确认信号，通过行锁或预期版本条件防止吞掉并发新变更。
不能先确认再持久化。确认字段仅供可信发布代码写入；Kubernetes 投递及各进程生效
需要独立的不可变发布记录和按绑定的序号，不能用此表的确认替代。本表不在每次模型
请求时查询。

本阶段**没有实现时钟到期任务、续期或故障新鲜度保证**。编辑到期时间会产生信号，
时间自然到达不会触发数据库事件。后续需将发布有效期限制在业务期限内、安排到期
任务，处理会话 token 存活及续期，避免靠周期清空未变化的策略满足续期，并在发布或
watch 故障时拒绝陈旧许可。这些集成门槛通过前保留现有安全鉴权路径。

## 验证

明确设置 `AEP_REFERENCE_TEST_DATABASE_URL` 指向允许创建数据库的可丢弃 PostgreSQL：

```sh
go test ./services/control-service/internal/repository -run TestModelAccess -race -count=1 -v
```

每个测试建立随机数据库，执行所有真实迁移，仅清理自己创建的数据库。覆盖角色
继承、员工独立身份、无关用户/部署不变、新旧绑定迁移、无关写入、事务回滚、级联
删除、ID 重用、并发版本与过时确认、成员/策略两个提交顺序，以及已有用户的升级迁移。
不设置该环境变量会跳过这些 PostgreSQL 测试；
Mock 不能替代真实数据库证据。不需要真实模型或客户凭据。
